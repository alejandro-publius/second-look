It runs inside make check. It fails on an em or en dash, an emoji, a middle dot separator, an

## The design review, top five, and what I did

The critic wrote none of the UI. It read UPDATE_06 and DESIGN.md, looked at eight screenshots, and
audited the code against every rule in Vercel's web interface guidelines. It found 28 things.
docs/reviews/DESIGN_REVIEW_01.md holds all of them and what happened to each.

1. **The share card was a different product.** Five off palette colours, a rounded pill progress
   bar and a system font, on the one artefact that leaves the app. Fixed: redrawn on the tokens
   through mirrored constants in app/theme.ts, with the staff gauge at poster size. The font is
   named rather than embedded, because an SVG served as an image cannot load one from us.
2. **The gauge failed contrast and lost its stripes.** The orange was under 3 to 1 against an
   empty block, and one empty block was indistinguishable from the next, which is most of the test.
   Fixed: an empty block is the surface with a line-strong edge, and the pair is now in the
   checker, proven by breaking a different token on purpose.
3. **A participant could lose answers silently.** The failed POST counter was written and never
   read. Fixed on the screen: one retry per answer, then a warning line with the offline icon for
   the rest of the run. Not fixed on the server: the API contract has no field for the count, so
   it is a planner question.
4. **No Back anywhere.** Fixed on consent and inside the lesson. Deliberately not on a test item:
   reaction time per item is a pre-registered outcome and a revision would change what is measured.
   The URL state for resume is still missing and is named as a gap.
5. **The primary button was near the top of short screens.** Sticky can hold an element up and can
   never push one down. Fixed: the flow is a flex column and the action bar takes the slack, which
   also stopped the bar covering the share card.

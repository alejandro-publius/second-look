## Did the full validator run, and what did it say

Yes. Not only the FHIR Shorthand compiler: the HL7 validator jar, version 6.10.4 (Git# 1b90fb13f77b),
FHIR R4 4.0.1, with their guide loaded from hl7-eu/oah at b907cf0, 510 resources loaded.

Every earlier run had terminology checking OFF, which is the part that matters most for P2, because
"a required binding our codes cannot meet" is one of the named fail conditions and terminology-off
hides exactly that. It was rerun with terminology ON against https://tx.fhir.org. The server really
answered, and it really did work: with terminology off the validator could not read the UCUM code
"m" and could not confirm the Location.type value set; with it on, the UCUM code passed and the
value set was expanded and judged.

**Result: 3 files, 0 errors, 23 warnings. P2 PASSES.** There are only two distinct warning texts:
fourteen dom-6 "a resource should have narrative" best practice notes, all of them on the hand
written example bundle and none on our emitter output, and nine Location.type extensible binding
misses where a SNOMED code for a creek is not in a value set of health care delivery sites, which
an extensible binding explicitly allows when nothing suitable exists. Our four feature codes sit
outside their OAH Indicators value set, and that lands as information only, because their
Observation profile binds Observation.code at preferred strength. No required binding blocks us and
nothing needed an invented extension, so no docs/ig_gap_report.md was written and fallback F2 is
not in force.

Two honest caveats. We model a citizen volunteer as a Practitioner. And their guide at b907cf0 has
no Practitioner, QuestionnaireResponse or Provenance profile at all, so P2's answer is only about
their Location and Observation profiles. Every error and warning, word for word and grouped by
resource, is in docs/notes/p2_validator_run.md.

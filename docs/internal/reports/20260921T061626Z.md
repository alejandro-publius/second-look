## The three things a judge would still find thin

1. **There is nothing to look at.** Every photograph in the product is a grey placeholder, so the
   two minute test, the lesson and the whole TRAIN verb read as scaffolding. That is a content
   problem on `main`, not a code problem, and it is one evening of picking. It is still the first
   thing anyone will notice.
2. **ACT is one page and half of it is empty.** `/city` is real and every number opens its
   records, but with no approved sentence it shows no measures, and with no visits it shows no
   findings. A judge opening it today sees the shape of an answer rather than an answer. The
   referral, the lab result coming back and the downstream note are the parts that would make it
   feel like a loop rather than a report.
3. **Nothing an agent can call.** The MCP server is the clearest "agents and integration" line in
   the rubric and it is not written. Our own read only FHIR endpoint exists, which is the hard
   half, but there is no tool a judge can point Claude at and watch it answer with resource ids
   attached.

Honourable mention, because it is cheap and it is missing: `make judge-check`. One command that
runs with no key and no network and prints five lines is worth more to a tired judge than another
page of documentation.

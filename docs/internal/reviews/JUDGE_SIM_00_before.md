# Judge simulation 00: the baseline, before the README is rebuilt

Six simulated judges, one per judge type in docs/internal/MASTER_BRIEF.md section 2, scored Second Look on 2026-09-22 (UTC) for docs/internal/updates/UPDATE_16A.md section 2. Each was a separate subagent that wrote none of the code. This is the "before" baseline; the rebuilt README from prompt 15 gets scored again later with the same inputs.

What each judge got, and nothing else:

- The README at commit 92fa280 on harden, the same README as 7acdb76 on depth.
- The live link, https://second-look-79t.pages.dev (production, built from main). GET only: no judge started the test, sent a form or used a browser. They read pages and the API routes those pages call. One judge also read the README's own sandbox link, Library/466, and Provenance/465: two read-only GETs, inside hard rule 10.
- The rubric and the organizers' five headers from the brief, section 2.
- Eight screenshots from docs/screens, fixed per judge so the "after" run can reuse the same set (listed under each judge).

Scores are 1 to 10. The weighted column uses the rubric weights: impact 30, innovation 20, technical 20, usability 15, feasibility 15 (percent).

## What all six said, in plain words

These are read across the six write-ups below; each point is made by at least four judges.

1. **The judge doors are broken on the live site.** /city?creek=strawberry-creek is a 404. /spot?id=example and /two load, then sit on "Loading the record" because the API routes they call (/api/spot/example, /api/two, /api/fhir/validation) answer 404. Production is built from main, and those routes live on depth. Five of the six named making these doors work as their one change; the sixth, the IEEE engineer, named running the model sweep and showing its table. All six put their change under technical.
2. **No results.** The Results section promises numbers and shows none: no model pass table, no named models, no participants. Several judges quote the brief back: last year the same organizers rewarded projects that reported results.
3. **The first screen of the README loses a reader in 30 seconds.** The four features are not named on the first screen. Line 9 ("The photographs land with the picks on main; this branch shows none rather than a stand in") reads as a note between developers and is out of date, since the live landing shows two real photos. "Flag", "passed" and "three models" come before they are defined. "Nobody is being recruited" sits next to "we check it on strangers".
4. **The screenshots show placeholders.** The docs/screens images the judges saw have gray PLACEHOLDER boxes, a placeholder lesson card and a placeholder contact email, while the live site already has real photos.
5. **Small contradictions a judge notices.** /how-we-know says prereg-v1 is "not yet tagged" while the README says it is tagged; the consent screen says four minutes while every other screen says two; the /city screenshot has raw URLs running off the card and "1 spots".

What they liked, in the same way: the idea itself (a per-feature score stored with every observation, and the AI held to the same test before it may speak), the pinned IG and a real Library entry on the sandbox, calling the hash chain an audit log and not a blockchain, and a clean phone flow with one question per screen.

Three things they would find thin:

1. No results at all. The README Results section says results arrive with the model run and shows no table. No model has been scored on the 16 photos, and no participants have taken part. So the two core claims, that the lesson helps and that the AI is only allowed to speak on features it passed, are both unmeasured. Last year these organizers rewarded projects that reported results.
2. The live demo does not match the README or the screenshots. /city?creek=strawberry-creek returns 404 even though the README lists it and screenshot 10 shows it. /spot?id=example and /two load, but their API calls return Not found, so a judge gets 'No record for this spot' and no lab-beside-volunteer view. /demo says judge mode opens Sep 28. 3. Trust from the volunteer to the record is thinner than the prose makes it sound. An observer is known only by a random browser token that clearing site data resets. So one person can pose as the 'two different people who both passed' that the rule needs before a pipe is listed for testing, and nothing signs or ties a score to a person. The audit log's head hash has not been published anywhere yet, the live How we know page says prereg-v1 is 'not yet tagged' while the test is already open, and the site gives a judge no way to check the chain.

### J02. The technical report prints two tables as raw pipe text, one of them on page 1
- Severity: major
- Where: docs/REPORT.pdf, pages 1 to 2 and 5 to 6; `unfolded` in scripts/build_report.py:148-153; scripts/tests/test_report_pdf.py:226.
- Compared: Every table in BlackBox's and Tideline's READMEs renders as a table. Second Look's own report at c0e9be7 held no raw table text.
- Evidence: I rendered all 7 pages with PyMuPDF. On page 1, under the Abstract and "1. The problem", about 30 lines run as one paragraph: "Every risk, what stops it, and the test that proves it | What can go wrong | What stops it, by construction | Proof | |---|---|---| | A volunteer walks past a built bank | ...". Its tail ("A refresh loses a session | ... | apps/web/tests/ |") opens page 2. Page 5 does the same with "Every surface of theirs we use, and where | Their surface | What we use it for | Where | |---|---|---| ...", on into page 6. The text of the c0e9be7 PDF has no "|---|"; this one has two. The cause is a0d4ba4. In `unfolded`, the pattern `^<summary>(.*?)</summary>\s*$` with re.M lets `\s*` eat the blank line after the summary, so the table follows the italic line with no blank line between them, and pandoc reads the table as text. Given "<summary>Every risk</summary>\n\n| a | b |\n|---|---|", it returns "*Every risk*\n| a | b |". The new test only checks that "*Every risk*" and "| a | b |" appear, so it passes. The report is a /judges door ("About fifteen minutes to read"), and issue #4 says it goes to Devpost as an attachment.
- Fix: Put a blank line after the italic summary line, for example by replacing it with `r"*\1*\n\n"` and using `[ \t]*$` in place of `\s*$`, then run `make report-pdf`. Make the test check for that blank line, or run pandoc on the output, and make the report build fail when the PDF text holds "|---|".

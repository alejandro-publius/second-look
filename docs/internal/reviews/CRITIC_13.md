### N01. make judge-check reports a false 'tap target measurement failed' whenever anything else is serving on port 3100, including the README's own make demo-offline and make dev
- Severity: minor
- Where: apps/web/scripts/design-check.mjs:233-247 (spawns npm run start, treats any 200 on 127.0.0.1:3100 as its own server, runs Playwright with PW_REUSE=1); scripts/judge_check.py:205-207 (no port check, prints only the last line); README.md:566-578 (Running locally: make demo-offline serves the site on 3100) and Makefile:16 and :27 (make dev and DEMO_WEB_PORT 3100); the README Quickstart says nothing about the port
- Compared: BlackBox's judge-check touches no server port and prints a PASS for each step on any machine. This repository's own apps/web/playwright.config.ts:29-32 knows about the trap for the e2e suite ('the run stops with a port in use error instead of testing it'), but design-check turns that guard off with PW_REUSE=1.
- Evidence: My first Quickstart run in a fresh clone printed 'FAIL web ... design-check failed: apps/web/tests/design.spec.ts:1 tap target measurement failed' (5 of 6). Another process may have held port 3100 at that moment, but I did not capture the cause. The design check alone then passed, and a second judge-check with a port watcher passed 6 of 6. Then I reproduced it on purpose, twice. (1) With python3 -m http.server serving on 127.0.0.1:3100, node scripts/design-check.mjs exited 1 with '3 failed' and the same line: it had measured the other app. (2) With make demo-offline running (next dev on 3100, as README Running locally says), it exited 1 with '1 failed, 2 passed': heading 'Before you start' was not found on /t, and then 'tap target measurement failed'. Neither message says the port was taken, and judge_check.py shows only the last line. A judge who tries Running locally and leaves it running, then runs the one command the README offers, gets a FAIL on the web step that points at tap targets.
- Fix: In design-check.mjs, check that 127.0.0.1:3100 is free before spawning, or wait for the spawned child's own ready line instead of any 200. If the port is taken, fail with 'port 3100 is in use by another process; stop it (make demo-offline and make dev use it) and run again', and have judge_check.py print that line. Add a test that runs design-check with a dummy server on 3100 and expects that message, and confirm it is red today. Or say in the Quickstart that judge-check needs port 3100 free.
